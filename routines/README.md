# Cloud scheduled tasks (formerly "routines")

Each `*.md` prompt here is pasted **verbatim** into one Claude Code cloud scheduled
task at [claude.ai/code/routines](https://claude.ai/code/routines). The prompts are
generated by `python routines/_build.py` from one shared SAFETY header and FINAL STEP,
and `tests/test_routines.py` fails if they drift from the builder or reference a
command or flag that doesn't exist.

**Editor-safe format.** The scheduled-task editor renders Markdown and keeps plain text, so the prompts
use no `<...>` (stripped as HTML), no backticks and no indented command lines (joined into one line).
Every command is its own `RUN:` paragraph; runtime values are `{{SLOT}}` placeholders defined in each
prompt's legend; each command computes the New York date itself. The CLI refuses empty arguments and
unfilled `{{...}}` slots. After saving a task, open it again and check that the `RUN:` lines and
`{{...}}` slots are still there.

> **Status: NOT ACTIVATED.** Don't create these tasks until `python -m xahil activation-check`
> passes its blocking checks. Even then, every order command stays in **dry-run** until you
> set both execution switches yourself.

## Who does what
| Layer | Responsibility |
|---|---|
| **Claude (the agent)** | Reads memory, does research, judges catalysts and thesis breaks, writes the logs, records decisions and evidence, writes the weekly review and strategy *proposals* |
| **`python3 -m xahil` (deterministic)** | Paper-only broker access, risk engine, protective-order selection, reconciliation, indicators, signals, regime, backtests, metrics, learning statistics, run claims, state-branch persistence, Telegram |

## Run flow (every workflow)
1. `run-claim`: restores `memory/` from the state branch, checks the calendar window and duplicates, then
   pushes this run's claim marker to the state branch and verifies it. Exit 0 = claimed; 5 = skip
   (done, running, closed, outside window, or another run won the race); 7 denied, 8 network, 9 conflict,
   1 error = stop (the tool alerts). Nothing else runs until the claim is verified on GitHub.
2. `preflight` → `reconcile` (Alpaca is the source of truth; detects resets, unexplained changes, unprotected positions).
3. Workflow steps.
4. `run-finish` → `guard` → `persist` (memory/ only, to the state branch, rebase on rejection, never force,
   never main). If the save fails, a recovery copy goes to the session's own `claude/*` branch and the owner
   is alerted; that copy is never read as shared memory or as a claim.

| Task | Cron (paste exactly) | ET | Allowed window (enforced by `run-claim`) | Main job |
|---|---|---|---|---|
| pre-market | `CRON_TZ=America/New_York 7 8 * * 1-5` | 08:07 | 06:00 to open−5 min | regime, signals, cited research, ideas, decisions |
| market-open | `CRON_TZ=America/New_York 47 9 * * 1-5` | 09:47 | open+10 to open+90 min | GTC protection first, then whole-share buys |
| midday | `CRON_TZ=America/New_York 7 12 * * 1-5` | 12:07 | open+90 to close−30 min (12:30 on half-days) | −7% cuts, stop tightening, thesis exits |
| daily-summary | `CRON_TZ=America/New_York 22 16 * * 1-5` | 16:22 | close+10 min to 20:00 | snapshot, P&L vs SPY, overnight-protection status |
| weekly-review | `CRON_TZ=America/New_York 7 10 * * 6` | Sat 10:07 | weekends, once per ISO week | weekly stats, learning analysis, monthly backtest, proposals |

Cron expressions are UTC unless they start with `CRON_TZ=`, so keep the prefix. Minutes
are set off the hour because on-the-hour runs can start several minutes late. Holidays and
half-days come from Alpaca's calendar.

## Fractional shares and overnight protection
- New entries must be **whole shares**: the risk engine rejects `--notional` and fractional quantities.
- A position counts as protected overnight only with an **open GTC stop or trailing stop on whole shares**. DAY stops (the only kind Alpaca allows on fractional shares) expire at the close and never count.
- While any position lacks GTC protection, **all new entries are refused**, Telegram alerts fire after the close, and `activation-check` is not ready.
- Even a GTC stop does not stop an overnight gap: a gap through the stop fills at the next open. The backtest models this (worst historical trade: −22.8% against a 10% stop).
- At the $100,000 baseline the position cap is about $5,000, so whole shares fit almost any US stock.

## Cloud environment (one environment shared by all five tasks)
1. **Network access → Custom**, allowed domains: `paper-api.alpaca.markets`, `data.alpaca.markets`,
   `api.telegram.org`, `api.tavily.com` (add `api.perplexity.ai` only if you approve Perplexity). Keep the
   default package-manager list checked.
2. **Network secrets** (recommended; the agent never sees the keys): "Alpaca paper" for hosts
   `paper-api.alpaca.markets` and `data.alpaca.markets`, two custom headers with no prefix:
   `APCA-API-KEY-ID` and `APCA-API-SECRET-KEY` (paper keys only). "Tavily" for host `api.tavily.com`:
   header `Authorization`, prefix `Bearer`, value your `tvly-` key, plus the variable `XAHIL_TAVILY_AUTH=proxy`.
   Optional later: Perplexity (`Authorization`, prefix `Bearer`).
3. **Environment variables**: `XAHIL_CLOUD=1`, `XAHIL_ALPACA_AUTH=proxy`, `XAHIL_TAVILY_AUTH=proxy`, `TELEGRAM_BOT_TOKEN`,
   `TELEGRAM_CHAT_ID`. Telegram puts its token in the URL, so it can't be a network secret. If
   network secrets don't work, use `XAHIL_ALPACA_AUTH=headers` with `ALPACA_API_KEY` /
   `ALPACA_SECRET_KEY` (paper, `PK…`). Never set `ALPACA_ENDPOINT` to anything but the paper URL.
4. **Do not** set `XAHIL_ORDER_EXECUTION`.
5. **Remove every connector from every task.** New tasks include all your claude.ai connectors by default, and
   some can trade or enable trading outside XAHIL's risk engine. XAHIL needs none.

## Repository and pushes (branch model)
| Branch | Holds | Who writes it |
|---|---|---|
| `main` | code, config, prompts, the rulebook | only you (Windows). Cloud runs never push it (the cloud proxy also refuses). |
| `claude/xahil-state` | the shared `memory/` (logs, snapshot, halts, run markers) | agent runs, normal fast-forward pushes only, `memory/` only |
| the session's own `claude/*` branch | a recovery copy after a failed final save | the failing run; you merge it with `state-recover` |

Select this repo, branch `main`, in every task. Cloud sessions may push `claude/*` branches but not
`main`, and cannot delete branches. `.gitattributes` merges append-only logs with Git's union driver;
any other conflict (snapshot, halts, run markers) stops the run rather than guessing. Settings live in
`config/persistence.json` (owner-controlled).

Owner commands (Windows):
- See the agent's memory: `git fetch origin claude/xahil-state` then `git log -p origin/claude/xahil-state -- memory/`.
- Check integrity: `python -m xahil state-audit` (only `memory/` differs from main, history never rewritten).
- Merge a recovery copy after an alert: `python -m xahil state-recover --branch claude/...` (asks you to type RECOVER).
- Delete leftover recovery branches yourself on GitHub; the cloud cannot delete branches.

## Activation (later, only with your explicit approval)
1. `python -m xahil activation-check` reports the blocking preconditions: paper account, equity within
   0.5x-3x of the $100,000 baseline, reconciled baseline, no halts, GTC protection on every position, Telegram, at least
   5 completed dry-run daily summaries and 1 weekly review.
2. Read the latest backtest report in `memory/backtests/` and the weekly learning analysis.
3. Only then, yourself: set `"order_execution_enabled": true`, `"approved_by"`, `"approved_on"` in
   `config/execution.json` (commit and push), **and** add `XAHIL_ORDER_EXECUTION=enabled` to the
   cloud environment.

Stop instantly: `"halt": true` in `config/execution.json`, `XAHIL_HALT=1` in the environment, or pause the tasks.
